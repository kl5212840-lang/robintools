# /audit — 全站内容健康审计

## 触发

用户输入 `/audit` 或 `/audit <范围>`。

- `/audit` — 审计全部内容文件
- `/audit articles` — 仅审计技术笔记
- `/audit guides` — 仅审计工具指南
- `/audit <tool-id>` — 仅审计指定工具（如 `/audit claude-code`）
- `/audit --deep` — 深度审计（含联网验证，耗时较长）

## 执行步骤

### 第 1 步：确定审计范围

读取以下文件作为搜索空间：

| 范围 | 文件 |
|------|------|
| 所有 | `src/content/articles/index.ts` + 9 篇 article .tsx + `src/content/guides/registry.ts` + 20 篇 guide .tsx + `src/content/tools.json` + `src/app/compare/page.tsx` |
| articles | `index.ts` + 9 篇 article .tsx |
| guides | `registry.ts` + 20 篇 guide .tsx |
| `<tool-id>` | `registry.ts` 中对应工具的 4 个 guide .tsx |

**注意**：guide .tsx 文件的行数差异很大（200-500 行）。只扫描渲染函数中实际包含内容的部分，跳过纯 import 和类型定义的头部。

### 第 2 步：执行检查项

每个检查项执行后，按严重程度分级输出：
- **❌ 必须修复**：影响内容准确性或用户可操作性
- **⚠️ 建议修复**：降低内容质量但不影响核心功能
- **💡 可优化**：锦上添花，不影响使用

#### 检查项 1：时效性标记

**规则**：如果内容中出现以下模式之一，下方必须有对应的时效性标注：

- 价格数字：`¥` / `$` / `元` / `/月` / `免费` / `Pro`
- 版本号：`v\d+\.\d+` / `version \d+`
- API 地址：`https://api.` / `base_url`

**检查方式**：
- 逐行扫描渲染函数
- 命中上述模式后，向后搜索 10 行内是否有：
  - `<FreshnessNote` 组件
  - "验证于" / "以上信息验证于" / "⚠️ 以上信息可能已过时"
  - `style={{ color: "var(--color-text-disabled)" }}`
- 如果没有，报告 ❌ 缺少时效性标注
- 如果有标注但日期距今 > 90 天，报告 ⚠️ 时效性标记过期

**输出格式**：`文件:行号` + 命中内容 + 类型

#### 检查项 2：命令可复制性

**规则**：`CodeBlock` 中的代码不应包含 shell 提示符。

**检查方式**：
- 搜索所有 `<CodeBlock` 的 `code={` 属性值
- 检查行首是否含 `$ ` / `# ` / `> ` / `PS> ` / `C:\> `
- 如果存在，报告 ❌ 命令含提示符

**不检查**：
- 代码块中 `# 注释` 开头的行为注释（不是 shell 提示符）
- 语言标注为 `text` 或 `plain` 的块

#### 检查项 3：平台内容隔离

**规则**：平台特定内容不能跨平台泄漏。

**检查方式**：
- 搜索包含 `isWin` 的渲染函数
- 在 `{isWin && (<>...</>)}` 块内搜索 Mac 独有命令：`brew`、`Homebrew`、`dmg`、`/Applications`
- 在 `{isMac && (<>...</>)}` 块内搜索 Win 独有命令：`winget`、`msix`、`exe`、`PowerShell`、`regedit`
- 在 `{!isWin && !isMac && (<>...</>)}` 块内搜索 Mac 独有命令（Linux 和 Mac 共用 `brew`？检查确实共用的场景不报）
- 如果发现泄漏，报告 ❌ 跨平台泄漏

**特例**：`CodeBlock` 中同时列了三种平台的命令（如 `# Linux:\nbrew install\n# macOS:\nbrew install`）且语言标记为 `bash` 的情况，不视为泄漏——这是故意展示对比。以此类推。

#### 检查项 4：标签一致性

**规则**：同一概念不应有多种写法。

**检查方式**：
- 收集 `index.ts` 中所有 `tags` 数组的值（去重）
- 对每个标签做归一化处理（全小写、去连字符、去空格）
- 找出归一化后相同但原文不同的对：
  - 如 `["claude-code", "ClaudeCode"]` → ⚠️ 标签写法不一致
  - 如 `["排查", "排错"]` → ⚠️ 标签同义词
  - 如 `["配置", "设置"]` → 💡 建议统一术语
- 检查指南 `registry.ts` 中 `searchText` 是否使用了与 `tags` 一致的关键词

**输出格式**：两个不一致的标签 + 建议统一为哪个

#### 检查项 5：元数据完整性

**规则**：每篇文章、每个指南必须有完整的元数据。

**文章检查**：
- `slug` 是否存在且非空
- `title` 是否存在且非空，≤ 60 字符
- `summary` 是否存在且非空，≤ 160 字符
- `date` 格式是否为 `YYYY-MM-DD`
- `tags` 数组是否有至少 2 个标签
- `render` 函数是否存在（import 有效）

**指南检查**：
- `steps` 数组是否有至少 2 个步骤
- 每个 step 是否有 `id`、`label`、`anchorId`
- `searchText` 是否非空且覆盖了核心关键词
- `render` 函数是否存在

缺失任何一项 → ❌ 元数据缺失

#### 检查项 6：内容结构

**规则**：指南和文章应有完整的结构。

**文章检查**（在渲染函数中）：
- 是否有 `<h2>` 标题（至少 1 个）
- 标题层级是否按序（h2 → h3 → h4，不跳级）
- 是否有至少一段正文（`<p>` 或等效文本节点）

**指南检查**（在渲染函数中）：
- 是否有 `<h2 id="section-...">` 开头的步骤标题
- 每个步骤标题是否有 `<span className="step-badge">` 编号
- 步骤数是否与 registry 中 `steps` 数量一致
- 步骤末尾是否有验证或后续指引

缺失 → ❌ 结构不完整

#### 检查项 7：注册一致性

**规则**：代码文件中存在的内容必须在注册表中注册。

**检查方式**：
- 列出 `articles/index.ts` 中所有 import 的文件名 → 记为集合 A
- 列出 `articleRegistry` 数组中所有条目的 `render` 引用 → 记为集合 B
- 列出 `src/content/articles/` 目录下所有 `.tsx` 文件（排除 `index.ts`）→ 记为集合 C
- A ≠ B → ❌ import 与注册表不一致
- C 中有但 A 中没有 → ❌ 有未导入的文章文件
- A ∪ B 中有的但 registry.ts 未引用 → ❌ 注册遗漏

**指南检查**：
- 列出 `registry.ts` 中所有 import 的文件路径 → 集合 A
- 列出 `guideRegistry` 对象中所有 render 引用 → 集合 B
- 列出 `src/content/guides/*/` 下所有 `.tsx` 文件（排除 `_shared.tsx`）→ 集合 C
- A ≠ B → ❌ import 与注册表不一致
- C 中有但 A 中没有 → ❌ 有未注册的指南文件

#### 检查项 8：对比表数据

**规则**：compare 页面中的价格、功能描述应有时效性标注。

**检查方式**：
- 读取 `src/app/compare/page.tsx`
- 检查页面底部是否有"内容验证于"或 `<FreshnessNote` 的标注
- 检查每个工具的数据对象是否至少有 `price` 和 `model` 字段
- 如果无时效性标注 → ⚠️ 对比表缺少时效性标注
- 如果有标注但日期 > 90 天 → ⚠️ 对比表时效性过期

#### 检查项 9：搜索覆盖

**规则**：新内容应有足够的搜索文本覆盖。

**检查方式**（仅对最近新增或修改的条目）：
- 检查文章的 `tags` 是否包含了关联的工具 ID（如提到 Claude Code 的文章应有 `claude-code` 标签）
- 检查指南的 `searchText` 是否覆盖了该步骤的核心概念和常见同义词
- 弱检查：`searchText` 长度 ≥ 20 字符 → 视为基本覆盖，否则 ⚠️ 搜索词可能不足

### 第 3 步：运行深度检查（仅 --deep 模式）

深度检查是可选的，需要联网。

#### 3.1 链接有效性

从所有文件提取 URL，对每个唯一 URL 执行 `WebFetch` 获取 HTTP 状态。只检查 `https?://` 开头的外部链接。跳过：

- 本站链接（`/claude-code` 等）
- `mailto:` 链接
- 已经标记为时效性过期的页面中的链接

#### 3.2 版本号对比

提取内容中的版本号模式（如 `v2.1.15`、`v4.x.x`），如果是 Claude Code、Cursor、Copilot、Windsurf 的版本号，WebFetch 对应工具的 changelog/releases 页面获取最新版本号对比。不强制执行——仅标注有差异且差异 > 1 个主版本的。

### 第 4 步：生成审计报告

```
📊 全站内容审计报告 — <YYYY-MM-DD>

   审计范围：<范围描述>
   文件数：<N>   检查项：9
   ─────────────────────────────────

❌ 必须修复（<N>）
   [时效性] <问题> — <文件:行号>
   [命令]   <问题> — <文件:行号>
   ...

⚠️ 建议修复（<N>）
   [标签]   <问题> — <文件:行号>
   [对比表] <问题> — <文件:行号>
   ...

💡 可优化（<N>）
   [搜索]   <问题> — <文件:行号>
   ...

   ─────────────────────────────────
   健康度：<❌ × X + ⚠️ × Y + 💡 × Z>
```

**健康度计算**（仅供趋势对比，不是绝对值）：
```
健康度 = 100 - (❌数 × 10) - (⚠️数 × 3) - (💡数 × 1)
≥ 90：良好   70-89：一般   < 70：需要集中修复
```

报告末尾附交互选择：

```
📋 下一步：

   [1] 修复第一个 ❌     → /edit 对应文件
   [2] 查看所有 ❌        → 重新列出所有必须修复项
   [3] 修复第一个 ⚠️     → /edit 对应文件
   [4] 深度审计           → /audit --deep
   [5] 保存报告           → 保存到 日志/audit-<YYYY-MM-DD>.md
   [6] 完成               → 结束

   输入数字：
```

**用户只需输入一个数字**。选择 1 或 3 后，修复完毕关掉 VSCode，/edit 会自动引导后续流程。

## 约束

- 全程 L1（只读扫描），不修改任何文件
- `--deep` 模式额外需要 WebFetch 权限
- 不遍历 `node_modules`、`.next`、`out`、`归档`、`教程搜集`、`文章草稿`
- 不确定的问题不标 ❌，标 ⚠️ 或直接跳过
- 审计范围限制在 `src/content/` + `src/app/compare/`
- 如果文件数为 0（罕见），报告"无内容文件"并退出
